# CLAUDE.md

## Vision

cikick is a CDK-style workflow manager for GitHub Actions, distributed on npm. Author workflows as TypeScript constructs, `cikick synth` emits `.github/workflows/*.yml`.

- Orgs/teams keep many repos up to date and secure by design.
- Workflows/jobs/config are shared as npm packages and fully customisable per repo: typed props → escape hatches (`addOverride` / `addDeletionOverride`) → aspects.
- Every action is pinned to a commit SHA via `cikick.lock.json`.
- Checks/aspects act as guards (`@cikick/policies`), including `enforceAfter` dates that escalate warn → error.
- Packages ship versioned migrations run by `cikick update` (Renovate `postUpgradeTasks`).
- The fleet control plane (`cikick-fleet`) acts ONLY on repositories the user explicitly selects, never the whole org: inventory, settings drift, secret age policy, multi-repo secret rotation (repo/env scopes).

User-facing overview: `README.md`. Docs: `docs-site/`.

## Invariants (do not break)

- Generated files carry the cikick header (`# Generated by cikick — do not edit`) and are never hand-edited. Fix the construct code and re-synth.
- Synth output is deterministic: stable key order, sorted lockfile. Re-running synth must produce no diff.
- `cikick check` must stay green on `examples/consumer` (and on the root dogfood config).
- Generated outputs (`.github/workflows/*.yml`, `cikick.lock.json`, `.nvmrc`, `renovate.json`) are excluded from oxfmt via `ignorePatterns` in `.oxfmtrc.json`. Add new generated paths there (release-please files and `CHANGELOG.md` too).
- Fleet commands refuse repos outside the selection; mutating commands (`settings apply`, `secrets rotate`) are dry-run unless `--yes`.
- Never log or print secret values.
- All GitHub I/O is injectable and mocked in tests (no network in tests).
- Node ≥22 everywhere; npm is the only runtime (no Bun/Deno-only APIs).

## Stack & commands

pnpm 10 workspaces, TypeScript ESM (NodeNext), tsdown builds (`.mjs` / `.d.mts`), vitest, oxlint, oxfmt.

```bash
pnpm install
pnpm build          # pnpm -r, concurrency 1 (packages depend on each other's dist)
pnpm test
pnpm typecheck
pnpm lint           # oxlint; warnings (e.g. no-explicit-any) are tolerated, errors are not
pnpm format         # oxfmt (also formats Markdown, including this file)
pnpm format:check
pnpm --filter @cikick/core test   # single package

# regenerate example output
cd examples/consumer && npx cikick synth && npx cikick check
```

- Build before testing cross-package changes: packages import each other's `dist`.
- After changing `bin` entries, run `pnpm install --force` to relink (otherwise `cikick` is "not found" in the consumer).
- Docs site: `pnpm --filter cikick-docs-site dev|build`.

## Conventions

- Use `.js` suffixes in TS import paths (NodeNext) and `import type` for type-only imports (lint-enforced).
- Construct idiom: `new X(scope, id, props)` without using the result. The `no-new` lint rule is off deliberately.
- Tests live in each package's `test/` dir (vitest).
- Migrations are semver-keyed `{ version, description, run(ctx) }`, run when `from < version <= to`, and must be idempotent. Use `ctx.deleteFile` / `ctx.writeFile`, not raw `fs`.
- Format: 120 cols, single quotes, trailing commas.
- `import/no-cycle` is an error.

## Known gaps / planned

- Fleet has never been run against real GitHub; it is only tested with mocked Octokit.
- `cikick-fleet secrets report` only uses `fleet.json` `secretPolicies`; it does not read each repo's cikick secrets manifest (PLAN.md describes this as intended).
- `cikick gen action` (typed action wrappers) is not built.
- This repo's workflows are generated from the root `cikick.config.ts`; never hand-write them. Run the root CLI with `pnpm cikick synth|check` (the workspace bin isn't linked before build).
- npm scope `@cikick` has old versions (core ≤0.4.0, cli ≤0.5.0, actions-common 0.3.0). Packages are baselined at 0.5.0 so the first release-please release is 0.6.0; deprecate the old versions (and `@cikick/actions-common`) afterwards.
