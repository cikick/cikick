# cikick — plan

CDK-style workflow manager for GitHub Actions, distributed as npm packages.

## Goals
1. Author workflows as TypeScript constructs; synth to `.github/workflows/*.yml`.
2. Share workflows/jobs/steps as npm packages, fully overridable per repo (escape hatches).
3. Pin every action to a commit SHA via `cikick.lock.json`; Renovate bumps packages, `cikick synth` regenerates.
4. Policies (aspects) and checks over the construct tree, repo files and GitHub repo settings.
5. Versioned migrations (codemods) shipped by packages, run by `cikick update` — Nx-style.
6. Fleet control plane over a **user-selected set of repositories** (not the whole org): inventory, settings drift, secret age policy, multi-repo secret rotation (repo/env scopes; org scope only if explicitly selected).

## Monorepo layout (pnpm workspaces, TS ESM, NodeNext, vitest)
| Package | Purpose |
|---|---|
| `packages/core` `@cikick/core` | constructs, synth, lockfile, aspects, checks, managed files, secrets declarations, migrations API |
| `packages/policies` `@cikick/policies` | stock aspects/checks (pin SHAs, explicit permissions, no `pull_request_target`+checkout, timeouts, deprecations) |
| `packages/cli` `@cikick/cli` | `cikick synth/check/lock/update/migrate` — loads `cikick.config.ts` (via `jiti`) |
| `packages/fleet` `@cikick/fleet` | `cikick-fleet select/inventory/settings/secrets/report` over user-chosen repos — Octokit, libsodium sealed boxes, HTML report |
| `examples/wf-node-ci` `@acme/wf-node-ci` | example shared package: construct + managed config + migrations |
| `examples/consumer` | example repo using it with overrides |

## Core API contract (all agents code against this)
```ts
// constructs: use the `constructs` npm package (Construct, IConstruct, Node)
class App extends Construct { constructor(opts?: { outdir?: string; lock?: Lockfile }); synth(): SynthResult }
class Workflow extends Construct { constructor(scope, id, props: WorkflowProps) // file = .github/workflows/<id>.yml
  addJob(id, props): Job; toObject(): object; addOverride(path: string, value: unknown) }
class Job extends Construct { addStep(step: StepProps): Step; permissions; needs; addOverride(path, value) }
interface StepProps { id?: string; name?: string; uses?: ActionRef | string; run?: string; with?: Record<string, unknown>; env?: Record<string,string>; if?: string }
class ActionRef { static of(spec: 'owner/repo[/path]@ref'): ActionRef; owner; repo; path?; ref; sha?: string }
class ManagedFile extends Construct { constructor(scope, id, { path, mode: 'managed'|'seeded'|'merged', content: object|string, format?: 'yaml'|'json'|'text', patchFile?: string }) }
class SecretDecl extends Construct { constructor(scope, id, { name, scope: 'repo'|'env'|'org', environment?, maxAgeDays?, provider?: string, description? }) }
// workflow expression helper: secret(name) => '${{ secrets.NAME }}' and registers SecretDecl usage

interface IAspect { visit(node: IConstruct): void }           // Aspects.of(scope).add(aspect) — may mutate
interface Check { id: string; severity: 'info'|'warn'|'error'; enforceAfter?: string /*ISO date: warn->error*/; 
  run(ctx: CheckContext): Finding[] | Promise<Finding[]> }
interface CheckContext { app: App; repoDir: string; readFile(p): string|undefined; settings?: RepoSettings }
interface Finding { checkId; severity; message; path?: string; fix?: () => void }
Checks.of(scope).add(check)

interface Lockfile { version: 1; actions: Record<'owner/repo@ref', { sha: string; resolvedAt: string }>; packages: Record<string, string> /*cikick pkg versions at last synth*/ }
interface ActionResolver { resolve(owner, repo, ref): Promise<string /*sha*/> }  // GitHubResolver(fetch, token) + LockResolver
async function synth(app, { repoDir, resolver?, frozen?: boolean }): Promise<SynthResult>
interface SynthResult { files: { path; content; mode }[]; lock: Lockfile; findings: Finding[] }
// Rendered action: `uses: owner/repo@<sha> # <ref>`. Generated files start with `# Generated by cikick — do not edit. Run \`npx cikick synth\`.`

interface Migration { version: string /*semver of the package that introduced it*/; description; 
  run(ctx: MigrationContext): Promise<void> }
interface MigrationContext { repoDir; readFile; writeFile; project: import('ts-morph').Project /*config file*/; log(msg) }
// packages export `cikick: { migrations: Migration[], checks?: Check[] }` from package.json field "cikick": "./dist/cikick.js"
```

## Config change handling (answer to "what if inputs/config change")
- Typed props → breaking prop change fails compile at synth.
- `ManagedFile` modes: `managed` (overwritten each synth, drift-checked), `seeded` (written once; future changes via migration), `merged` (base deep-merged with repo-owned `patchFile`).
- `cikick update`: compares `lock.packages` with installed versions; runs each package's migrations with `from < version <= to` in order; then synth.
- Checks with `enforceAfter` nudge manual migrations (warn → error after date).

## Fleet control plane (`@cikick/fleet`)
Scope is **only the repositories the user selects** — never implicitly "all repos in the org".
- `cikick-fleet select`: lists repos the authenticated user can administer (`GET /user/repos?affiliation=owner,organization_member` filtered to `permissions.admin`), optional `--owner`/`--filter` glob, interactive multi-select (`@inquirer/prompts` checkbox) or non-interactive `--add owner/repo --remove owner/repo`. Persists to `fleet.config.ts`/`fleet.json` in the user's chosen dir (e.g. a personal "fleet" repo).
- `fleet.json`: `{ repos: ["owner/repo", ...], groups?: { name: ["owner/repo"] }, settingsPolicy, secretPolicies: [{ name, scope: 'repo'|'env', environment?, maxAgeDays, repos?: string[] /*subset or group*/ }] }`. Every command accepts `--repos`/`--group` to narrow further; refuses to touch a repo not in the selection.
- `inventory`: per selected repo — cikick lock (packages + pinned actions) read via contents API, generated-header presence, action SHAs in use.
- `settings diff|apply`: default workflow permissions read, allowed actions, actions enabled, rulesets/branch protection presence. `apply` is dry-run unless `--yes`.
- `secrets report`: repo/env secrets of selected repos, `updated_at` vs `maxAgeDays`, plus secrets declared in each repo's cikick manifest but missing.
- `secrets rotate <NAME> [--group g] --value-from-env VAR|--value-from-stdin`: public key → libsodium sealed box → PUT on each selected repo/env; dry-run unless `--yes`.
- `report --html out.html`: static dashboard of the selection.
- All GitHub I/O behind an injected Octokit for tests (mocked).
